- Correction (after the study's hard stop, pod clock about 02:55 UTC on 2026-11-23): the "no tokens" errors in the mistral.rs runs are not engine failures. They are completions whose first token is end-of-text, which the load generator records as an error because it requires a non-empty text chunk. Evidence: in an fp32 PEFT reference, end-of-text is the top first token for adapter 4 on the two prompts that fail in every run (rank 1, logprob -3.7 and -3.0); requests that flip between runs sit in near-ties (first-token logprobs within 0.1 to 0.2). Open: vLLM and SGLang recorded 0 errors in 30,000 adapter requests each against 10 in 9,000 for mistral.rs (8 on adapter 4), but on different prompt and adapter mixes, so a cross-engine difference is not established and was not tested.
